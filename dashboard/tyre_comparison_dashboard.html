Upload a document

Drop in a filing, transcript, or annual report excerpt (.txt or .pdf) — Claude reads it, detects the reporting currency/unit, pulls a short source quote for each figure, and adds the record automatically. Uploading again for the same company and quarter updates that record instead of duplicating it.

Every quoted figure is then checked back against the document you uploaded before anything is stored. A figure whose quote can't be found — or whose quote doesn't contain the number — is re-extracted once and, if it still doesn't check out, the record is not saved. Records that pass arrive as pending and wait for you in Review. The document itself is read in memory for this run and never saved.

Not stored — these figures could not be traced to the document

The extraction was retried once with the failing fields named. It still could not produce a quote that both appears in your document and contains the figure, so nothing was written to storage — a record that fails this check must not reach the reviewer looking like it passed.

The Excel export is a four-sheet workbook — Core Financials, Segments, Outlook, Sources & Quotes — and every populated Core Financials cell carries a comment with the source quote behind it, so a number can be checked without leaving the file. "Approved records only" is on by default: an export is reviewed data unless you deliberately say otherwise. The CSV above is unchanged (one flat sheet, all records, normalized to ₹ crore). One honest caveat about formatting: this page loads the community build of SheetJS, whose writer ignores per-cell styling — column widths and the cell comments come through, but bold headers and wrapped text are dropped, and freeze panes may be too. The data and the traceability are unaffected, which is what the workbook is for.

The PowerPoint export is the same data as a deck: a title and provenance slide, one comparison slide per metric group, channel and product mix, outlook themes, a slide per company, and a closing slide saying plainly what quote verification does not catch. It obeys the same "Approved records only" tick, and a company nobody has reviewed is marked with an asterisk on every slide it appears on. Rejected records are never included, with the box ticked or not. The file is built here in the browser with no library — node pipeline/deck.mjs renders the identical slides from the identical code.

"Restore / import JSON" takes either a backup from this dashboard or a records.json written by the Node pipeline (and a bare array of records). Each record is validated on the way in, anything malformed is listed rather than silently dropped, and imported records arrive pending. A review decision is only carried in where this browser already holds that exact record unchanged, so the decision was demonstrably made here — a file cannot import its own approvals.

Review — nothing is trustworthy until a person says so

Every record from every source lands here as pending, including records that were already in this browser before the review gate existed. Each figure is shown next to the exact quote stored for it and how that quote checked out against the source document, so a whole run of companies is one pass instead of one review per company. There is deliberately no bulk approve and no auto-accept at any scale: approval is one considered click per record.

Ask about the stored records

Questions are answered only from the records in this browser — the whole set by default, so cross-company questions ("which company has the best EBITDA margin", "which ones mentioned rising rubber costs") work properly. Any number in an answer comes with the quote stored for it; if the records don't contain the answer, the answer says so instead of guessing. Records you rejected are withheld, and records still pending review are declared as such.

What this page does and does not do

Short version, so nothing here is a surprise.

Manual trigger onlyNothing runs on a schedule. Extraction happens when you press "Upload and add"; a question is asked when you press "Ask". There is no polling, no timer, and no code path that re-runs itself.
No storage of source documentsAn uploaded filing is read into memory, used for extraction and for checking quotes, and dropped when the run ends. Only the extracted record and its quotes are saved.
No fabricated quotes, no estimated numbersThe extraction prompt forbids both, and the quote check enforces the first one: a quote that isn't in your document fails, and so does a real quote that doesn't contain the figure it was cited for.
